    付録Aコマンドチートシート

    分類コマンド覚え方・備考
    ファイル操作ls / cd / pwd / mkdir / rm / cp / mv / find / touch第1回。rm -rf は最終確認してから
    テキストcat / less / head / tail / grep / wc / vitail -f と grep はログ調査の相棒
    パーミッションchmod / chown / ls -lr=4, w=2, x=1
    ユーザadduser / usermod / userdel / su / sudo / whoami通常は一般ユーザ、必要時のみsudo
    サービスsystemctl start/stop/restart/enable/status / journalctl -u変更後は daemon-reload
    監視top / uptime / free -h / df -h / ps aux / vcgencmd measure_tempload average はコア数と比較
    ネットワークip a / hostname -I / ping / ss -tlnp（UDPは -ulnp）/ ufw開けるポートは必要最小限
    アーカイブtar czf / tar xzf / tar tzfc=作成, x=展開, t=一覧
    スケジュールcrontab -e / crontab -l / timedatectl分 時 日 月 曜日
    Dockerdocker ps / logs / exec / compose up -d / compose downデータはボリュームに置く

    付録BトラブルシューティングFAQ

    症状確認すること
    SSHで接続できない電源とWi-Fi設定を確認。.local がだめならIPアドレスで接続。ping が通るか確認
    サービスが起動しないjournalctl -u luanti -e でエラーを読む。パスの誤字、chown忘れ、daemon-reload忘れが三大原因
    ゲームから接続できないsystemctl status（稼働しているか）→ ss -ulnp（30000を待ち受けているか）→ ufw status（開いているか）の順に切り分け。LuantiはUDPなので ss は -u で見る
    サーバが重い（ラグい）top で load average を確認。接続人数を減らす、負荷設定（active_block_range等）を見直す。vcgencmd measure_temp で熱も疑う
    ディスクがいっぱいdf -h で確認 → du -sh ~/backup 等で犯人を探す。バックアップの世代数（KEEP）を見直す
    Dockerコンテナがすぐ落ちるdocker ps -a で状態確認 → docker compose logs でエラーを読む。ボリュームの所有者（PUID/PGID）の不一致も定番の原因
    機材の不調（SDカード・Pi本体・BYOD）自分で分解・復旧を試みず、教員・支援員に申し出て予備機材と交換する。SDカード破損時は新しいSDで起動し、直近のバックアップから復旧する（第4回の手順）
    初回起動で Failed to open "/var/log/luanti/default.log"Debianパッケージの既定のログ先に一般ユーザは書けない。コマンドと ExecStart に --logfile "" を付けているか確認（2-3）
    起動時に Failed to setup server ports（CivetServer）30000番の取り合い。付属サービス luanti-server が動いている（2-2）か、自分の luanti サービスが動いたまま手で起動している。sudo ss -tulnp | grep 30000 で持ち主を確認し、止めてから起動する
