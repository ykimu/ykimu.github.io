    3.1CLIとGUI

    コンピュータの操作方法には、マウスで画面上の部品を操作するGUI（Graphical User Interface）と、文字でコマンドを打ち込むCLI（Command Line Interface）の2つの様式がある。日常の利用にはGUIが便利だが、サーバ管理の世界では今もCLIが主役である。理由は3つある。第一に、操作を正確に記録・伝達できる。「この辺をこうクリックして……」ではなく、コマンドをそのまま書き写せば、誰でも寸分違わず同じ操作を再現できる（本資料や指導書のコード枠がまさにそれである）。第二に、自動化できる。CLIの操作はそのままシェルスクリプトやcronに載せられるが、GUIのクリック操作の自動化は難しい。

    第三に、軽い。GUIは描画のために多くのメモリとCPUを消費する。実習で使ったRaspberry Pi OS「Lite」はGUIを持たない構成であり、節約した資源をすべてLuantiサーバに回せている。

    CLIの入口となる画面をターミナル（端末）と呼ぶ。そしてターミナルの向こう側で、入力されたコマンドを解釈・実行しているプログラムがシェルである。両者はセットで語られることが多いが、ターミナルは「窓口」、シェルは「通訳」と役割が異なる。

    ターミナルterminal
    文字を入出力するための窓口となる画面。実習でBYODからsshして開くのも、この窓口である（第1回 1-3）。
    シェルshell / bash
    入力されたコマンドを解釈し、カーネルに実行を依頼するプログラム。人間とカーネルの間に立つ通訳にあたる。実習の標準はbashである。

    3.2シェルは何をしているのか

    ターミナルに ls -l /home と入力してEnterを押したとき、シェル（bash）は次の仕事をしている。

    1. 入力を単語に分解する（コマンド名 ls、オプション -l、引数 /home）。
    2. コマンドの実体を探す。
    3. 見つけたプログラムを実行するようカーネルに依頼する。
    4. プログラムの出力を受け取って画面に流す。
    5. 終了を検知して次の入力を待つ。

    つまりシェルは「人間とカーネルの間に立つ通訳」である。GUIのファイルマネージャと違い、操作を文字で正確に表現できるため、記録・再現・自動化（シェルスクリプト）が容易であることがCLI最大の利点である。

    3.3コマンドはどこにあるのか：PATHの仕組み

    ls と打つだけで /usr/bin/ls が実行されるのは、シェルが環境変数PATHに列挙されたディレクトリを先頭から順に探すからである。echo $PATH を実行すると /usr/local/bin:/usr/bin:/bin のようなコロン区切りのリストが表示される。

    「command not found」というエラーは、①コマンド名の打ち間違い、②未インストール、③インストール先がPATHに入っていない、のいずれかを意味する。which コマンド名 で実体の場所を確認できる。cronに登録するコマンドを絶対パスで書くのも、cronの環境ではPATHがほとんど設定されていないからである（第8章 8.3）。

    PATH環境変数
    シェルがコマンドの実体を探すディレクトリのリスト。コロン区切りで、先頭から順に探される。echo $PATH で内容、which ls で実際に選ばれる実体を確認できる。
    よくある誤解・トラブル コード枠の $ も一緒にコピーして貼り付ける

    $ はシェルが表示しているプロンプト（入力待ちの目印）であって、打ち込む文字ではない。本サイトのコード枠は$を含まない形でコピーされるので、そのまま貼り付けてよい。

    command not found が出たら、そのソフトが入っていないという意味だ

    原因は3つある。打ち間違い、未インストール、PATHに入っていない場所にある、のいずれかである。まず綴りを見直し、次に which コマンド名 で実体を探す。

    3.4環境変数と設定ファイル

    シェルの動作を調整する設定値は環境変数として保持される。値の確認は echo $変数名、一時的な変更は export 変数名=値 で行う。exportによる変更はそのシェルを閉じると消えるため、永続化したい設定は ~/.bashrc（シェル起動のたびに読み込まれる）に書き込む。書き込んだ直後は source ~/.bashrc で再読み込みすると反映される。

    環境変数environment variable
    シェルとその配下のプログラムが参照する設定値。echo $変数名 で確認し、export 変数名=値 で変更する。変更はそのシェルを閉じると消える。
    環境変数意味
    PATHコマンドを探すディレクトリのリスト
    HOME自分のホームディレクトリ（~ の実体）
    USER現在のユーザ名
    LANG言語・地域設定（ja_JP.UTF-8 など）
    PS1プロンプトの表示内容
    HISTSIZEコマンド履歴の保存件数
    EDITOR標準のテキストエディタ

    3.5標準入出力とリダイレクト

    すべてのコマンドは、3本の「配管」を持って生まれる。標準入力（stdin、番号0）、標準出力（stdout、番号1）、標準エラー出力（stderr、番号2）である。通常はいずれも端末につながっているが、この配管をつなぎ替えるのがリダイレクトとパイプである。エラーメッセージが標準出力と別の配管（stderr）になっているのがポイントで、「正常な結果はファイルへ、エラーは画面へ」といった振り分けができる。

    標準エラー出力stderr（番号2）
    エラーメッセージが流れる出口。標準出力（番号1）とは別の配管なので、> でファイルに送っただけではエラーは記録されない。両方まとめたいときは 2>&1 を付ける。
    リダイレクトの書式
    ls > list.txt # 標準出力をファイルへ（上書き）
ls >> list.txt # 標準出力をファイルへ（追記）
ls 2> error.txt # 標準エラー出力をファイルへ
ls > all.txt 2>&1 # 両方を同じファイルへ
wc -l < list.txt # ファイルを標準入力として与える

    実習の第5回でcronに書いた「> …/status.txt 2>&1」は、「正常な出力もエラーも同じファイルに書き出す」という意味だったことが、ここまで読むと分かるはずである。

    よくある誤解・トラブル > でファイルに保存すれば、エラーも残る

    > が拾うのは標準出力だけで、エラーは画面に出たまま消える。ログとして残したいときは 2>&1 を付けて標準エラー出力も同じ先へ送る。

    > を何度か実行して、結果を溜めていく

    > は毎回上書きである。追記したいときは >> を使う。大事なファイルに > を向けると中身が一瞬で空になるので、書き先の名前は打つ前に確認する。

    パイプ「|」は、あるコマンドの標準出力を次のコマンドの標準入力に直結する。ls | wc -l、grep xxx log.txt | sort | uniq -c のように、小さな道具を組み合わせて複雑な処理を組み立てるのがUNIX流である。1つのコマンドの出力を「次の道具の材料」と考える発想に慣れると、コマンドラインの応用力が一気に上がる。

    パイプ|
    あるコマンドの標準出力を、次のコマンドの標準入力に直結する記号。ls | wc -l のように、小さな道具をつないで複雑な処理を組み立てられる。

    3.6その他の便利機能

    • ワイルドカード：* は任意の文字列、? は任意の1文字に展開される。rm world_*.tar.gz のようにまとめて指定できる。展開はシェルが行っており、コマンド自身は展開後のファイル名リストを受け取っている。
    • クォート：空白や記号を含む文字列は "二重引用符" で囲む。シェルスクリプトで変数を "$SRC" のように囲むのは、値に空白が含まれても1つの引数として扱われるようにするためである。
    • 履歴と補完：↑↓で履歴を辿り、Ctrl+Rで検索できる。Tabキーの補完はコマンド名・ファイル名の打ち間違いを防ぐ最も簡単な方法であり、常用すべきである。

    3.7パイプの道具箱（sort・uniq・cut・xargs）

    パイプ（3.5節）の真価は、小さな道具の組み合わせで集計や一括処理を組み立てられることにある。実習では、backup.shの世代削除（第4回 4-2）や「プレイヤーごとの入室回数ランキング」（第3回の発展課題）がその実例である。部品となる道具を整理する。

    コマンドはたらき
    sort行を並べ替える。-n 数値順、-r 逆順、-h サイズ表記（1K, 2Gなど）順
    uniq -c連続する重複行をまとめて数える。事前に sort しておくのが約束
    cut -d区切り -f列各行から指定した列を取り出す（例：cut -d: -f1 で /etc/passwd のユーザ名）
    wc -l行数を数える（第1回の演習で使用）
    xargs標準入力をコマンドの引数に変換する。-r は入力が空なら何もしない
    組み合わせの実例
    grep "joins game" ログ | sort | uniq -c | sort -nr # 頻度集計の型
ls -1t world_*.tar.gz | tail -n +8 | xargs -r rm -- # 世代削除（第4回）
cut -d: -f1 /etc/passwd | sort | head # ユーザ名の一覧
    補足

    ※ 集計の定石は「絞り込む（grep）→ 列を取り出す（cut）→ 並べる（sort）→ 数える（uniq -c）→ 多い順に並べ直す（sort -nr）」。この型を覚えると、ログ解析（第3回 3-6）の応用範囲が一気に広がる。

    よくある誤解・トラブル uniq -c を使ったのに、同じ名前が何度も別々に数えられる

    uniq がまとめるのは連続した重複行だけである。数える前に sort で同じ行を隣り合わせておく必要がある。

    ls ... | xargs rm は、対象がなければ何も起きない

    入力が空でも rm は起動してしまうことがある。xargs -r を付けると、入力が空のときはコマンド自体を実行しない。backup.shの世代削除でこの書き方をしているのはそのためである。

    3.8bashを速く正確に使う

    サーバ管理では、同じコマンドを何度も打ち、長いパスを正確に入力する場面が続く。打鍵を減らすことは、単に楽をするためではなく、打ち間違いによる事故を減らすためである。ここでは履歴・別名・クォート・展開・終了コードという、bashを安全に速く使うための5つの仕組みを整理する。

    履歴を使い回す

    bashは実行したコマンドを記憶しており、↑で1つずつ遡れる。しかし100回前のコマンドを↑で探すのは現実的でない。実用になるのはCtrl+Rによる検索で、押したあとに一部の文字を打つと、それを含む直近のコマンドが呼び出される。さらにCtrl+Rを押すと、より古い一致へ移動する。Enterで実行、Escまたは→で編集に移れる。

    履歴の使い方
    history # 履歴を番号付きで一覧
history | grep systemctl # 履歴から探す
!! # 直前のコマンドをもう一度
sudo !! # 直前のコマンドをsudoを付けてやり直す
ls -l ~/server/luanti.conf
vi !$ # 直前のコマンドの最後の引数を使い回す
!123 # 履歴番号123のコマンドを実行
    操作意味例
    Ctrl+R履歴を後ろ向きに検索する。繰り返し押すと次の一致へ打ってから systemctl
    !!直前のコマンド全体sudo !!
    !$直前のコマンドの最後の引数vi !$
    !文字列その文字列で始まる直近のコマンド!systemctl
    Ctrl+A / Ctrl+E行頭へ／行末へ移動する長いコマンドの修正時
    Ctrl+U / Ctrl+Kカーソルより前を／後ろを消す打ち直すとき
    注意

    sudo !!は便利だが、直前のコマンドが何だったかを確認せずに使ってはいけない。rmを含むコマンドが権限不足で失敗したあとにsudo !!を打つと、今度は本当に消える。危険なコマンドのやり直しは↑で呼び戻し、内容を目で読んでからEnterを押すこと。

    alias と ~/.bashrc

    よく使う長いコマンドには別名（alias）を付けられる。ただしaliasをその場で実行しても、そのシェルを閉じれば消える（3.4節）。恒久的にしたいなら~/.bashrcに書き足す。~/.bashrcはシェルが起動するたびに読み込まれる設定ファイルで、環境変数もここで設定する。

    ~/.bashrc に書き足す例（末尾に追記）
    # 自分用の設定（ここから）
alias ll='ls -alF'
alias la='ls -A'
alias lt='ls -lt'
alias df='df -h'
alias jl='journalctl -u luanti -n 50 --no-pager'
export HISTSIZE=5000
export HISTCONTROL=ignoredups
# 自分用の設定（ここまで）
    設定の反映と確認
    cp ~/.bashrc ~/.bashrc.bak # 編集前に必ず控えを取る
vi ~/.bashrc
source ~/.bashrc # 開いているシェルに反映させる
alias # 現在有効な別名の一覧
type ll # 別名が効いているかの確認
\ls # 別名を一時的に無視して本来のコマンドを実行
    よくある誤解・トラブル ~/.bashrc に書いたのに、別名が効かない

    編集しただけでは、いま開いているシェルには読み込まれない。source ~/.bashrcを実行するか、いったんログアウトして入り直す。

    危険を防ぐため alias rm='rm -i' にしておけば安心だ

    自分の環境では確認が出るようになるが、スクリプトの中や他のユーザ、別のサーバでは効かない。別名に頼った安全は、環境が変わった瞬間に失われる。確認する習慣そのものを身につけるほうが確実である。

    クォートと展開

    シェルはEnterの直後、コマンドを実行する前に文字列を書き換えている（3.2節）。この書き換えを展開という。どこまで展開させ、どこから文字どおりに扱わせるかを決めるのがクォートである。3種類の使い分けを覚えれば、空白を含むファイル名や記号で失敗しなくなる。

    書き方意味例と結果
    'シングルクォート'中身を完全に文字どおり扱う。展開は一切されないecho '$HOME' → $HOME
    "ダブルクォート"空白はまとめるが、$変数とコマンド置換は展開されるecho "$HOME" → /home/taro
    \（バックスラッシュ）直後の1文字だけを文字どおり扱うecho \$HOME → $HOME
    * ?ファイル名に展開される（該当が無ければそのまま残る）ls *.conf
    {a,b} {1..5}括弧展開。ファイル名の有無に関係なく文字列を作るecho file{1..3} → file1 file2 file3
    $(コマンド)コマンドの出力に置き換わるecho $(date +%Y%m%d)
    クォートquoting
    シェルによる展開をどこまで許すかを決める引用符。シングルクォートは中身を完全に文字どおり扱い、ダブルクォートは$変数とコマンド置換だけを展開する。空白を含むファイル名を1つの引数にまとめる役割もある。
    クォートと展開を試す
    echo "今日は $(date +%Y-%m-%d) です" # 変数とコマンド置換は展開される
echo '今日は $(date) です' # シングルなら文字どおり
cp ~/server/luanti.conf{,.bak} # 括弧展開で「同じ名前+.bak」を作る定番の書き方
mkdir -p ~/work/{src,log,tmp} # 3つのディレクトリを一度に作る
touch "my file.txt" # 空白を含む名前はクォートで1つの引数にする
ls -l "my file.txt"

    出力の読み方：同じechoでもクォートの種類で結果が変わることを確かめる。

    クォートの違いの出力例
    echo "$HOME"
/home/taro
echo '$HOME'
$HOME
echo file{1..3}.txt
file1.txt file2.txt file3.txt
cp ~/server/luanti.conf{,.bak}
ls ~/server
luanti.conf  luanti.conf.bak  world

    ダブルクォートでは$HOMEが値に置き換わり、シングルクォートでは文字のまま残る。この違いが分かっていれば、シェルスクリプトで「変数を展開したいのか、記号を守りたいのか」を意識して書けるようになる（第9章）。cp file{,.bak}はcp file file.bakに展開される慣用表現で、設定ファイルを編集する前の控えを最短で作れる。ワイルドカードと違い、括弧展開は実在するファイルと無関係に文字列を作る点が重要である。

    終了コードとコマンドの連結

    すべてのコマンドは、終わるときに0から255の数値（終了コード）を残す。0が成功、0以外が失敗を表す。直前の終了コードは変数$?で読める。この値をもとに次の動作を決めるのが&&と||であり、実習で何度も書いたsudo apt update && sudo apt install -y vimは、「更新が成功したときだけ導入する」という意味だった（第1回 1-7）。

    終了コードと連結
    ls /etc/hostname
echo $? # 直前の終了コード（0なら成功）
ls /no/such/file
echo $? # 0以外なら失敗
sudo apt update && sudo apt upgrade -y # 前が成功したときだけ次を実行
systemctl is-active luanti || sudo systemctl start luanti # 前が失敗したときだけ次を実行
cd ~/server; ls # セミコロンは成否に関係なく順に実行
    終了コードexit status / $?
    コマンドが終わるときに残す0から255の数値。0が成功、0以外が失敗を表す。直前の値はecho $?で読め、&&（成功なら次へ）と||（失敗なら次へ）の判断材料になる。

    出力の読み方：成功と失敗で$?の値がどう変わるかを見る。

    終了コードの出力例
    ls /etc/hostname > /dev/null; echo $?
0
ls /no/such/file 2> /dev/null; echo $?
2
systemctl is-active luanti
active
echo $?
0

    成功なら0、失敗なら0以外という約束は、すべてのコマンドに共通である。systemctl is-activeが典型で、画面にactiveと出すだけでなく終了コードでも成否を返すため、スクリプトやcronからそのまま条件として使える（第9章、第5回 5-4）。2や1といった具体的な数値の意味はコマンドごとに違うので、manのEXIT STATUSの項を読む。

    出力を分岐させる（2>&1・tee・xargs）

    3.5節のリダイレクトを、実務でよく使う3つの形にまとめる。2>&1はエラーも同じ行き先へ送る指定、teeは画面に出しつつファイルにも残す分岐、xargsは前のコマンドの出力を次のコマンドの引数に変える変換器である。

    出力の取り回し
    ./backup.sh >> ~/backup/run.log 2>&1 # 出力もエラーも同じファイルへ追記（順序が重要）
df -h | tee ~/disk.txt # 画面に出しつつファイルにも保存
df -h | tee -a ~/disk.txt # 追記する
echo 'Luanti実習サーバ（メンテナンス予定は掲示を確認）' | sudo tee /etc/motd # 管理者権限でファイルに書く定番
ls -1t ~/backup/world_*.tar.gz | tail -n +8 | xargs -r rm -- # 新しい7件を残して削除
find ~/server -name '*.conf' -print0 | xargs -0 ls -lh # 空白入りの名前でも壊れない形
    書き方意味注意点
    > file 2>&1標準出力とエラーを同じファイルへ順序が逆（2>&1 > file）だとエラーは画面に残る
    > /dev/null出力を捨てる2> /dev/nullならエラーだけ捨てる
    | tee file画面とファイルの両方へ分岐-aを付けないと上書きになる
    | sudo tee file管理者権限が要るファイルへ書き込むsudo echo ... > fileは権限不足で失敗する
    | xargs -r cmd入力を引数に変えて実行。-rは空なら実行しない空白を含む名前は-print0と-0で対処
    | xargs -I{} cmd {}引数の位置を自分で指定する1件ずつ実行されるので遅い
    よくある誤解・トラブル sudo echo "行" > /etc/xxx.conf で管理者用のファイルに書ける

    リダイレクトを行うのはsudoではなく、それを起動したシェル（一般ユーザ）である。そのためPermission deniedになる。echo "行" | sudo tee /etc/xxx.confと書くのが定石である。

    cmd 2>&1 > log.txt と cmd > log.txt 2>&1 は同じだ

    順番で意味が変わる。2>&1は「その時点の標準出力と同じ行き先」を指すので、先に書くとまだ画面を指しており、エラーは画面に出たままになる。ログに両方残したいときは必ず> log.txtを先に書く。

    3.9テキスト処理の道具箱

    Linuxの設定もログも、ほとんどがテキストである（第2章 2.1）。だから「テキストを絞り込み、切り出し、数える」道具を使えることが、そのままサーバの調査能力になる。ここでは3.7節の一覧を、コマンドごとの実用オプションまで掘り下げる。

    grep：まず絞り込む

    調査はいつも「大量の行から関係する行だけを取り出す」ことから始まる。それがgrepである。基本形はgrep 探す語 ファイルで、ファイル名を省くと標準入力（パイプの前段の出力）を対象にする。

    grep の実用形
    grep 'error' ~/backup/backup.log # 単純に含む行を探す
grep -i 'error' ~/backup/backup.log # 大文字小文字を区別しない
grep -n 'max_users' ~/server/luanti.conf # 行番号を付ける
journalctl -u luanti | grep -c 'joins game' # 該当した行数を数える
grep -v '^#' ~/server/luanti.conf | grep -v '^$' # コメントと空行を除いて設定だけ見る
grep -rn 'luanti' /etc/systemd/system/ # ディレクトリ以下を再帰的に探す
grep -E 'error|failed|warn' ~/backup/backup.log # 複数の語のいずれか
    オプション意味例
    -i大文字小文字を区別しないgrep -i error log
    -n行番号を付ける。viで直す前に位置を知るgrep -n max_users conf
    -rディレクトリ以下を再帰的に探すgrep -rn luanti /etc
    -c一致した行数だけを出すgrep -c error log
    -v一致しない行を出す。除外に使うgrep -v '^#' conf
    -E拡張正規表現を使う。|で「または」grep -E 'a|b' log
    -A N / -B N一致行の後ろ／前をN行も表示するgrep -A 3 error log

    出力の読み方：-nや-rを付けたときに増える列の意味を確認する。

    grep の出力例
    grep -n 'max_users' ~/server/luanti.conf
5:max_users = 5
grep -rn 'ExecStart' /etc/systemd/system/
/etc/systemd/system/luanti.service:10:ExecStart=/usr/games/luantiserver --world /home/luanti/server/world --gameid minetest --config /home/luanti/server/luanti.conf --logfile ""
journalctl -u luanti | grep -c 'joins game'
37

    -nを付けると行番号:内容、-rを付けるとファイル名:行番号:内容という形になる。この形はそのまま「どのファイルの何行目を直せばよいか」の指示書になる。-cは行数だけを返すので、「エラーが今日何回出たか」のような集計に向く。^#の^は行頭を表す正規表現で、-vと組み合わせたgrep -v '^#'は設定ファイルから実際に効いている行だけを抜き出す定番である。

    正規表現regular expression
    文字列の形を表す記法。^は行頭、$は行末、.は任意の1文字を表す。grep -v '^#'のように「コメント行を除く」といった指定ができる。

    切り出す・数える（cut・tr・wc・head・tail）

    絞り込んだあとは、必要な列だけを取り出して数える。cutは区切り文字で列を切り、trは文字を置き換えたり削ったりし、wcは数える。headとtailは先頭と末尾を切り出すが、tail -fだけは性格が違い、ファイルが伸びるのを画面で待ち続ける「監視」の道具になる。

    切り出しと集計
    cut -d: -f1 /etc/passwd # コロン区切りの1列目（ユーザ名）
cut -d: -f1,3 /etc/passwd # 1列目と3列目
cut -c1-8 ~/backup/backup.log # 各行の1文字目から8文字目まで
echo 'hello' | tr 'a-z' 'A-Z' # 小文字を大文字に
cat ~/backup/backup.log | tr -s ' ' # 連続する空白を1つにまとめる
wc -l ~/backup/backup.log # 行数を数える
tail -n 50 ~/backup/backup.log # 末尾50行
tail -f ~/backup/backup.log # 追記されるのを待ち続ける（Ctrl+C で終了）
    コマンド主なオプション意味
    cut-d区切り -f列番号区切り文字で切って指定の列を取り出す
    cut-c範囲文字位置で切り出す（固定幅のログ向き）
    tr'a-z' 'A-Z'文字を1対1で置き換える
    tr-d 文字 / -s 文字削除する／連続を1つにまとめる
    wc-l / -w / -c行数／単語数／バイト数を数える
    head / tail-n N先頭／末尾のN行を出す
    tail-f追記を待ち続けて画面に流す
    tail-n +NN行目から最後まで（tail -n +8で8件目以降）
    実習ではここで使う

    ※ tail -fはログを見ながら操作するときの基本姿勢である。第3回 3-6 演習：ログ解析ではgrepとcutとuniq -cを組み合わせ、第4回 4-2のbackup.shではtail -n +8で古い世代を選んでいる。

    awk と sed の最小限

    awkとsedは単独で1冊の本になるほど大きな道具だが、サーバ管理で日常的に使うのはごく一部である。ここでは覚える価値の高い形だけに絞る。awkは「空白区切りのN列目を取り出す」、sedは「範囲を表示する」と「文字列を置き換える」の3つを覚えれば、当面は足りる。

    awk と sed の実用形
    ps aux | awk '{print $1, $2, $11}' # 1列目・2列目・11列目だけを出す
df -h | awk '{print $5, $6}' # 使用率とマウント先だけ
awk -F: '{print $1}' /etc/passwd # 区切りをコロンに変える（cutと同じ働き）
awk -F: '$3 >= 1000 {print $1}' /etc/passwd # 条件を付けて絞る（一般ユーザだけ）
sed -n '1,5p' ~/server/luanti.conf # 1行目から5行目だけを表示
sed 's/30000/30001/' ~/server/luanti.conf # 各行の最初の一致を置換して表示（ファイルは変わらない）
sed -i.bak 's/30000/30001/g' ~/server/luanti.conf # ファイルを書き換える（.bakに原本を残す）
    注意

    sed -iはファイルを直接書き換える。置換の指定を間違えると設定ファイルが壊れ、サービスが起動しなくなる。必ず先に-iを付けずに実行して結果を画面で確かめ、そのうえで-i.bakのように控えを残す形で実行すること。控えがあればmv luanti.conf.bak luanti.confで戻せる。

    出力の読み方：列番号の数え方と、置換が反映される範囲を確認する。

    awk と sed の出力例
    df -h | awk '{print $5, $6}'
Use% Mounted
16% /
0% /dev/shm
13% /boot/firmware
awk -F: '$3 >= 1000 {print $1, $3}' /etc/passwd
taro 1000
luanti 1001
sed -n '1,3p' ~/server/luanti.conf
# サーバ名（自由に付けよう）と、接続時に表示されるメッセージ
server_name = taroのサーバ
motd = ようこそ！

    awkの$1は1列目、$5は5列目で、区切りは既定では空白である。df -hの見出し行も一緒に処理されるため、1行目にUse% Mountedという列名が混ざる点に注意する。見出しを除くにはdf -h | tail -n +2 | awk ...のように前段で落とす。-F:でコロン区切りに変えればcut -d:と同じことができるが、awkは$3 >= 1000のような条件を書ける点で強い。UID 1000以上が人間のユーザだという約束は第5章で扱う。

    よくある誤解・トラブル sed 's/a/b/' を実行したのに、ファイルの中身が変わらない

    sedは既定では結果を画面に出すだけで、ファイルは書き換えない。書き換えるには-iが要る。逆に言えば、-iを付けずに試せば安全に結果を確認できる。

    sed 's/a/b/' で行中のすべての「a」が置き換わる

    既定では各行の最初の1つだけである。すべてを置き換えるには末尾にgを付けてs/a/b/gとする。

    3.10長時間コマンドと端末の切り離し

    バックアップ、大量のファイルの圧縮、aptの大規模な更新。数分から数十分かかる処理をSSH越しに実行したとき、途中で回線が切れたらどうなるか。既定では、その処理も一緒に終了してしまう。ここではその理由と、3つの対処法を扱う。

    前面・背面とジョブ制御

    端末で実行中のコマンドは前面（フォアグラウンド）にあり、その間ほかの操作はできない。末尾に&を付けると背面（バックグラウンド）で動き、すぐプロンプトが戻る。前面のコマンドをCtrl+Zで一時停止してbgで背面に回すこともできる。これらをまとめてジョブ制御と呼ぶ（第6章 6.4）。

    ジョブ制御
    tar czf ~/backup/world_test.tar.gz -C ~/server world & # 最初から背面で実行
jobs # 背面のジョブの一覧
fg %1 # 1番のジョブを前面に戻す
bg %1 # 一時停止中の1番を背面で再開する
wait # 背面のジョブがすべて終わるまで待つ

    出力の読み方：ジョブ番号とPID、そして状態を確認する。

    jobs の出力例
    jobs
[1]+  Running                 tar czf /home/taro/backup/world_test.tar.gz -C /home/taro/server world &
jobs -l
[1]+  1842 Running                 tar czf /home/taro/backup/world_test.tar.gz -C /home/taro/server world &

    角括弧の中がジョブ番号で、fgやbgでは%1のように指定する。+は「既定で対象になるジョブ」の印である。Runningは実行中、StoppedはCtrl+Zで一時停止中を意味する。-lを付けると表示されるのがPIDで、これはpsやkillで使う番号と同じである（第6章 6.1）。ジョブ番号は端末ごとの通し番号にすぎず、別の端末からは見えない点に注意する。

    nohup：切断されても止めない

    SSHが切れると、その端末につながっていたプロセスにはHUP（hangup、回線切断）というシグナルが送られ、既定ではそれを受けて終了する。nohupはこのシグナルを無視させるコマンドで、nohup コマンド &の形で使えば、ログアウトしても処理が続く。出力先を指定しないとnohup.outというファイルに溜まるので、明示的にログへ流すほうがよい。

    SIGHUPhangup / nohup
    端末が切断されたときに、その端末で動いていたプロセスへ送られるシグナル。既定ではこれを受けて終了する。nohupを前に付けると無視させられるので、ログアウトしても処理が続く。
    nohup の使い方
    nohup ~/backup.sh > ~/backup/nohup.log 2>&1 & # 切断されても続く形
echo $! # いま背面に回したプロセスのPID
tail -f ~/backup/nohup.log # 進捗をログで追う
ps -p PID -o pid,etime,cmd # まだ動いているかを確認
    補足

    ※ nohupで走らせた処理は、あなたがログアウトしても動き続けるが、サーバを再起動すれば当然消える。「再起動しても勝手に立ち上がる」ことを求めるなら、それはsystemdのサービスにすべき対象である（第6章 6.2、第2回 2-5）。nohupは「今回だけ長く走らせたい」一時的な処理のための道具である。

    tmux：作業そのものを置いておく

    nohupは処理を切り離すだけで、画面は失われる。「作業中の端末ごと」サーバに置いておき、あとで別の場所から同じ画面に戻りたい場合に使うのがtmuxである。SSHが切れても、サーバ側ではセッションが生き続けている。翌日、別のPCからSSHしてtmux attachすれば、昨日の画面がそのまま現れる。

    tmux の最小操作
    sudo apt install -y tmux # 導入（Raspberry Pi OS Liteには入っていない）
tmux new -s work # work という名前でセッションを作って入る
tmux ls # 動いているセッションの一覧
tmux attach -t work # work に戻る
tmux kill-session -t work # 不要になったセッションを片付ける
    操作意味備考
    tmux new -s 名前名前を付けてセッションを開始する名前を付けないと数字になり分かりにくい
    Ctrl+B のあと d切り離す（detach）。処理は動いたまま端末だけ抜ける最重要の操作
    tmux ls生きているセッションの一覧何も無ければno server running
    tmux attach -t 名前切り離したセッションに戻る別のPCからSSHしても戻れる
    Ctrl+B のあと c / n新しいウィンドウを作る／次へ移る1セッション内で画面を増やせる
    exitそのウィンドウを閉じる。最後の1つならセッションも終わるdetachとは違う点に注意
    tmuxterminal multiplexer
    サーバ側に端末の作業画面を置いておける道具。Ctrl+Bのあとdで切り離すと、SSHが切れても中の処理と画面が残り、tmux attachで同じ状態に戻れる。

    出力の読み方：切り離したあと、セッションが生きていることを一覧で確かめる。

    tmux ls の出力例
    tmux ls
work: 1 windows (created Sat Sep 19 14:20:11 2026)
tmux attach -t work
(昨日と同じ画面がそのまま表示される)

    work:がセッション名、1 windowsがその中の画面数、括弧内が作成時刻である。(attached)と付いていれば、今どこかの端末から接続されている状態を意味する。tmux lsがno server running on /tmp/tmux-1000/defaultと答えたら、生きているセッションは1つも無い。Ctrl+Bは「これからtmuxへの命令を送る」という合図（プレフィックスキー）で、続けて押すキーで動作が決まる。まずはd（切り離し）だけ覚えれば十分である。

    よくある誤解・トラブル 長い処理は & を付けて背面に回しておけば、SSHが切れても安全だ

    &だけでは端末につながったままなので、切断されると一緒に終了する。切断に耐えさせたいならnohupかtmuxを使う。

    tmuxから抜けるときは exit でよい

    exitはウィンドウを閉じる操作で、最後の1つなら作業ごと終了してしまう。処理を残したまま抜けるのはCtrl+Bのあとd（detach）である。
