シェルスクリプト入門

シェルスクリプトは、シェルに打ち込むコマンドをファイルにまとめたもので、一度手で成功させた作業を二度と間違えずに再実行できるようにする。

このページ

    9.1シェルスクリプトとは

    シェルスクリプトは、シェルに打ち込むコマンドをファイルにまとめたものである。手作業の記録がそのままプログラムになるため、「一度手で成功させた作業を、二度と間違えずに再実行できる」のが本質的な価値である。運用作業（バックアップ、デプロイ、集計）の自動化は、ほとんどここから始まる。

    1行目の #!/bin/bash はシバン（shebang）と呼ばれ、「このファイルは /bin/bash で実行せよ」という宣言である。スクリプトの実行には、実行権を付与して ./backup.sh とする方法と、bash backup.sh とシェルに直接渡す方法がある。前者にはシバンと実行権（chmod +x）が必要で、こちらが実務の標準である。

    9.2基本文法

    シェルスクリプトの基本要素
    #!/bin/bash
NAME="world" # 変数（= の前後に空白を入れない）
echo "target is $NAME" # 参照は $変数名。"" 内では展開される
DATE=$(date +%Y%m%d) # コマンド置換：実行結果を変数へ
if [ -d "/home/luanti/server/$NAME" ]; then # 条件分岐
echo "found"
else
echo "not found"; exit 1 # 異常終了（終了コード1）
fi
for f in *.tar.gz; do # 繰り返し
echo "$f"
done
    要素説明
    $1, $2, …, $#スクリプトに渡された引数（1番目、2番目、…、個数）
    $?直前のコマンドの終了コード。0が成功、0以外が失敗
    [ 条件 ]テスト。-d（ディレクトリがある）、-f（ファイルがある）、-z（空文字）など
    && ／ ||前のコマンドが成功したら／失敗したら次を実行（cd "$DEST" || exit 1）
    "$変数"変数は常に二重引用符で囲む（空白入りの値でも安全に扱うため）

    9.3backup.shを読み解く

    実習第4回のbackup.shは、基本要素の実践例になっている。改めて各行の意図を追ってみよう。SRC・DEST・KEEPを冒頭で変数にしたのは、設定を1か所に集めて変更しやすくするためである（マジックナンバーを本文に散らばらせない）。DATE=$(date +%Y%m%d_%H%M%S) はコマンド置換で実行時刻をファイル名に埋め込み、世代を区別する。cd "$DEST" || exit 1 は「移動に失敗したらそこで止める」安全装置で、もしこれがないと、移動失敗時に意図しないディレクトリで削除処理が走る危険がある。世代削除の1行は、ls -1t（新しい順に1列で表示）→ tail -n +8（8行目以降＝8世代目以降の古い世代）→ xargs -r rm（それらをrmに渡す。-rは対象なしなら何もしない）というパイプの合わせ技である。同じ発想で、tarの行に || { 作りかけのファイルの削除; 失敗の記録; exit 1; } を付けておくと、「バックアップが失敗したのに完了と記録される」事故も防げる（指導書のbackup.shはこの形にしている）。

    9.4スクリプトのデバッグ

    スクリプトが思いどおりに動かないときは、当てずっぽうに書き換える前に「どの行まで進み、変数に何が入っているか」を見えるようにする。最も手軽なのは bash -x による実行トレースと、echoによる変数の確認である。

    デバッグの基本道具
    bash -x ~/backup.sh # 実行しながら各行と変数の展開を表示
echo "DEST=$DEST" # 変数の中身を見る。原始的だが最強
    スクリプト冒頭に書く安全装置
    #!/bin/bash
set -eu

    set -e はコマンドが失敗した時点でスクリプトを止め、-u は未定義の変数をエラーにする。backup.sh の cd "$DEST" || exit 1 のような明示的な安全装置と併用するとよい。また、静的検査ツールのshellcheck（Webブラウザ版もある）は、引用符の付け忘れなど定番のミスを自動で指摘してくれる。最終課題でスクリプトを書くときの心強い味方である。

    Note

    ※ 「手で実行すると動くのにcronだと動かない」ときは、まず絶対パスとPATH（8.3節）を疑う。bash -x の出力をリダイレクトでログに残しておくと、cron環境での調査も速くなる。
