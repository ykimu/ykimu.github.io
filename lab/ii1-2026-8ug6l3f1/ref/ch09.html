    9.1シェルスクリプトとは

    シェルスクリプトは、シェルに打ち込むコマンドをファイルにまとめたものである。手作業の記録がそのままプログラムになるため、「一度手で成功させた作業を、二度と間違えずに再実行できる」のが本質的な価値である。運用作業（バックアップ、デプロイ、集計）の自動化は、ほとんどここから始まる。

    シェルスクリプトshell script
    シェルに打ち込むコマンドを順に並べたテキストファイル。新しい言語を覚えるのではなく、普段のコマンドをそのまま書けばよい。

    1行目の #!/bin/bash はシバン（shebang）と呼ばれ、「このファイルは /bin/bash で実行せよ」という宣言である。スクリプトの実行には、実行権を付与して ./backup.sh とする方法と、bash backup.sh とシェルに直接渡す方法がある。前者にはシバンと実行権（chmod +x）が必要で、こちらが実務の標準である。

    シバンshebang / #!
    スクリプトの1行目に書く #!/bin/bash のこと。どのプログラムでこのファイルを解釈するかをカーネルに伝える。
    よくある誤解・トラブル ./backup.sh と打ったのに Permission denied と言われる

    スクリプトに実行権が付いていない。chmod +x ~/backup.sh を実行するか、その場しのぎなら bash ~/backup.sh とシェルに直接渡す。なお、実行権のないファイルは ls -l の並びに x が出ない（第5章）。

    スクリプトを置いたディレクトリで backup.sh と打てば動くはず

    カレントディレクトリはPATHに含まれないのが普通なので、./backup.sh のように「どこにあるか」を明示する必要がある。

    9.2基本文法

    シェルスクリプトの基本要素
    #!/bin/bash
NAME="world" # 変数（= の前後に空白を入れない）
echo "target is $NAME" # 参照は $変数名。"" 内では展開される
DATE=$(date +%Y%m%d) # コマンド置換：実行結果を変数へ
if [ -d "/home/luanti/server/$NAME" ]; then # 条件分岐
echo "found"
else
echo "not found"; exit 1 # 異常終了（終了コード1）
fi
for f in *.tar.gz; do # 繰り返し
echo "$f"
done
    要素説明
    $1, $2, …, $#スクリプトに渡された引数（1番目、2番目、…、個数）
    $?直前のコマンドの終了コード。0が成功、0以外が失敗
    [ 条件 ]テスト。-d（ディレクトリがある）、-f（ファイルがある）、-z（空文字）など
    && ／ ||前のコマンドが成功したら／失敗したら次を実行（cd "$DEST" || exit 1）
    "$変数"変数は常に二重引用符で囲む（空白入りの値でも安全に扱うため）
    コマンド置換$(コマンド)
    コマンドの実行結果を、その場の文字列として埋め込む書き方。DATE=$(date +%Y%m%d) のように、実行時の日付をファイル名に入れるときに使う。
    終了コードexit status / $?
    コマンドが終わるときに返す数値で、0が成功、0以外が失敗を表す。直前のコマンドの値は $? で読め、&& や ||、if の判定もこの値を見ている。
    よくある誤解・トラブル 代入は NAME = "world" と書いても同じ

    シェルでは = の前後に空白を入れてはいけない。空白を入れると「NAMEというコマンドを引数付きで実行する」と解釈され、command not found になる。

    変数を引用符で囲むかどうかは好みの問題

    囲まないと、値に空白が含まれたときに複数の引数に分解される。rm $DEST のような行では、意図しないファイルを消す事故につながる。変数は常に "$DEST" と囲む。

    9.3backup.shを読み解く

    実習第4回 4-2のbackup.shは、基本要素の実践例になっている。改めて各行の意図を追ってみよう。SRC・DEST・KEEPを冒頭で変数にしたのは、設定を1か所に集めて変更しやすくするためである（マジックナンバーを本文に散らばらせない）。DATE=$(date +%Y%m%d_%H%M%S) はコマンド置換で実行時刻をファイル名に埋め込み、世代を区別する。

    cd "$DEST" || exit 1 は「移動に失敗したらそこで止める」安全装置で、もしこれがないと、移動失敗時に意図しないディレクトリで削除処理が走る危険がある。世代削除の1行は、ls -1t（新しい順に1列で表示）→ tail -n +8（8行目以降＝8世代目以降の古い世代）→ xargs -r rm（それらをrmに渡す。-rは対象なしなら何もしない）というパイプの合わせ技である。

    同じ発想で、tarの行に || { 作りかけのファイルの削除; 失敗の記録; exit 1; } を付けておくと、「バックアップが失敗したのに完了と記録される」事故も防げる（指導書のbackup.shはこの形にしている）。失敗を失敗として記録することが、自動化の最低条件である。このスクリプトを第4回 4-3でcronに載せると、以後は人が見ていない時間に動き続けることになる。

    世代削除の行に見られるように、小さな道具をパイプでつないで目的の処理を組み立てるのがシェルの流儀である（第3章）。

    9.4スクリプトのデバッグ

    スクリプトが思いどおりに動かないときは、当てずっぽうに書き換える前に「どの行まで進み、変数に何が入っているか」を見えるようにする。最も手軽なのは bash -x による実行トレースと、echoによる変数の確認である。

    デバッグの基本道具
    bash -x ~/backup.sh # 実行しながら各行と変数の展開を表示
echo "DEST=$DEST" # 変数の中身を見る。原始的だが最強
    スクリプト冒頭に書く安全装置
    #!/bin/bash
set -eu

    set -e はコマンドが失敗した時点でスクリプトを止め、-u は未定義の変数をエラーにする。backup.sh の cd "$DEST" || exit 1 のような明示的な安全装置と併用するとよい。

    また、静的検査ツールのshellcheck（Webブラウザ版もある）は、引用符の付け忘れなど定番のミスを自動で指摘してくれる。最終課題（第6回 6-1）でスクリプトを書くときの心強い味方である。

    set -eu
    スクリプト冒頭に書く安全装置。-e はコマンドが失敗した時点で実行を止め、-u は未定義の変数の参照をエラーにする。
    bash -x
    スクリプトを実行しながら、各行と変数の展開結果を表示するトレース実行。「どの行まで進み、変数に何が入っているか」を直接目で見るための第一の道具。
    よくある誤解・トラブル set -eu を書けば、どんな失敗でも必ず止まる

    万能ではない。if の条件や || の左側など、失敗が前提の場所では止まらず、パイプの途中のコマンドが失敗しても最後のコマンドが成功すれば通過してしまう。重要な行には || exit 1 を自分で付けるのが確実である。

    手で実行して動いたのだから、cronでも同じように動くはずだ

    cronの実行環境は対話シェルとは別物で、PATHも短く、~ の展開や作業ディレクトリの前提も異なる。パスは絶対パスで書き、出力はログにリダイレクトして残す（第4回 4-3、8.3節）。

    補足

    ※ 「手で実行すると動くのにcronだと動かない」ときは、まず絶対パスとPATH（8.3節）を疑う。bash -x の出力をリダイレクトでログに残しておくと、cron環境での調査も速くなる。

    9.5文法リファレンス

    9.2節では最小限の文法だけを示したが、実際に運用スクリプトを書き始めると、引数の受け取り方や安全装置の書き方が必要になる。ここではそれらを「書くときに引く順」で並べる。文法は暗記するものではなく、必要になったときに正しい形を写せばよい。

    変数と展開

    変数は「名前=値」の1行で作る。= の前後に空白を入れないこと、参照するときは二重引用符で囲むこと、この2つが事故を防ぐ原則である。値に空白が含まれていても、囲んであれば1つの値として扱われる。

    変数と展開の書き方
    #!/bin/bash
DEST="$HOME/backup"          # 代入。= の前後に空白を入れない
KEEP=7                       # 数値もそのまま書く（型はない）
DATE=$(date +%F)             # コマンド置換
TOTAL=$((KEEP * 2))          # 算術展開（整数のみ）
echo "保存先は $DEST です"     # "" の中では $ が展開される
echo '保存先は $DEST です'     # '' の中では展開されない
echo "${DATE}_world.tar.gz"  # 変数名の切れ目を {} で明示する
    書き方意味例
    "$VAR"値の展開。空白入りでも1つの値として渡るrm -- "$FILE"
    ${VAR}変数名の範囲を明示する。直後に文字が続くとき必須"${DATE}_world"
    ${VAR:-既定値}未設定または空なら既定値を使う（VARは書き換えない）KEEP="${KEEP:-7}"
    ${VAR:?メッセージ}未設定ならメッセージを出して即座に終了するDEST="${DEST:?保存先が未設定}"
    $(コマンド)コマンド置換。実行結果を文字列として埋め込むNOW=$(date '+%F %T')
    $((式))算術展開。整数の計算に使う$((KEEP + 1))
    $? ／ $$直前の終了コード ／ 実行中のスクリプト自身のPIDTMP="/tmp/work.$$"
    パラメータ展開parameter expansion
    ${VAR:-既定値} のように、変数の値を取り出すときに既定値や検査を同時に行う書き方。設定漏れのまま処理が進む事故を、1行で防げる。

    クォートの規則

    シェルのつまずきの多くは引用符に由来する。覚えるのは3つだけである。二重引用符は変数とコマンド置換だけを展開し、単引用符は何も展開せず文字どおりに扱う。バックスラッシュは直後の1文字だけを文字として扱う。

    クォートの効き方を確かめる
    NAME="my world"
echo "$NAME"
my world
echo '$NAME'
$NAME
echo \$NAME
$NAME
ls "$NAME"      # 1つのディレクトリ名として渡る（正しい）
ls $NAME        # my と world の2引数に分解される（事故のもと）
ls: cannot access 'my': No such file or directory
ls: cannot access 'world': No such file or directory
    注意

    ※ 引用符を省いた rm -rf $DEST は、DEST が空のときに rm -rf だけが残り、値に空白が入っていれば複数の対象を消しにいく。削除を伴う行では、変数を必ず "$DEST" と囲み、${DEST:?} で未設定を弾き、-- を付けてオプション誤認を防ぐ。この3点セットは習慣にしてよい。

    条件判定：test と [ ] と [[ ]]

    if が見ているのは「コマンドの終了コードが0かどうか」だけである。[ 条件 ] は test というコマンドの別名であり、角括弧の内側には必ず空白が要る。bashでは [[ 条件 ]] も使え、こちらは変数の分解が起きないぶん安全で、文字列の一致にパターンを書ける。移植性が要るときは [ ]、bash前提でよいときは [[ ]] と使い分ければよい。

    条件真になるとき例
    -f パス ／ -d パス通常ファイルである ／ ディレクトリである[ -d "$DEST" ]
    -e パス ／ -s パス存在する ／ 存在してサイズが0でない[ -s "$LOG" ]
    -r ／ -w ／ -x読める ／ 書ける ／ 実行できる[ -x /usr/games/luantiserver ]
    -z 文字列 ／ -n 文字列空である ／ 空でない[ -z "$1" ]
    "$a" = "$b" ／ !=文字列として等しい ／ 等しくない[ "$MODE" = "full" ]
    -eq -ne -lt -le -gt -ge整数として等しい、異なる、より小さい など[ "$USED" -ge 80 ]
    ! ／ -a ／ -o否定 ／ かつ ／ または（[[ ]] では && ||）[ ! -d "$DEST" ]
    条件分岐の基本形
    #!/bin/bash
DEST="$HOME/backup"
if [ ! -d "$DEST" ]; then
  mkdir -p "$DEST"
elif [ ! -w "$DEST" ]; then
  echo "保存先に書き込めない: $DEST" >&2
  exit 1
fi
# [[ ]] ならパターンも書ける（右辺は引用符で囲まない）
if [[ "$(hostname)" == mc-* ]]; then
  echo "実習用のサーバである"
fi
    よくある誤解・トラブル if [$# -eq 0] と書いたら unary operator expected と言われる

    [ はコマンド名なので、その後ろに空白が必要である。if [ "$#" -eq 0 ] と、角括弧の内側の両端に空白を入れる。

    数値の比較にも = を使えばよい

    [ "$USED" = "80" ] は文字列比較なので、080 と 80 は別物と判定される。数値は -eq や -ge を使う。逆に文字列の比較に -eq を使うと integer expression expected になる。

    繰り返しと分岐：for・while・case

    運用スクリプトでよく使う形は3つである。ファイルを1つずつ処理する for、コマンドの出力を1行ずつ読む while read、引数の値で処理を振り分ける case である。

    for・while・case
    #!/bin/bash
# 1) ファイルを1つずつ処理する
for f in "$HOME"/backup/*.tar.gz; do
  [ -e "$f" ] || continue        # 1件もないときは *.tar.gz のまま渡るので弾く
  echo "$f"
done

# 2) 数値を数える（seq を使わない書き方）
for i in {1..5}; do echo "回数 $i"; done

# 3) コマンドの出力を1行ずつ読む
df -h --output=pcent,target | tail -n +2 | while read -r pcent target; do
  echo "$target が $pcent"
done

# 4) 引数で処理を振り分ける
case "${1:-status}" in
  start)  systemctl start luanti ;;
  stop)   systemctl stop luanti ;;
  status) systemctl is-active luanti ;;
  *)      echo "使い方: $0 {start|stop|status}" >&2; exit 2 ;;
esac

    while read -r 行 の -r は、バックスラッシュを特別扱いしないための指定であり、付けるのが既定と考えてよい。break で繰り返しを抜け、continue で次の周回に進む。case の各枝は ;; で閉じ、*) が「どれにも当てはまらないとき」である。

    関数と引数

    同じ処理が2回出てきたら関数にする。関数の中でも引数は $1、$2 で受け取れる（スクリプト自身の引数とは別物になる）。全部まとめて次のコマンドに渡したいときは "$@" を使う。"$*" は全体が1つの文字列に潰れてしまうので、通常は "$@" が正しい。

    引数の受け取りと関数
    #!/bin/bash
usage() {                       # 関数の定義
  echo "使い方: $0 <世代数> [保存先]" >&2
  exit 2
}

[ "$#" -ge 1 ] || usage         # 引数が足りなければ使い方を出して終了
KEEP="$1"                       # 1番目の引数
DEST="${2:-$HOME/backup}"       # 2番目。省略時は既定値
echo "引数の個数: $#"
echo "スクリプト名: $0"
echo "全部まとめて: $@"
    変数意味例
    $0実行されたスクリプト自身の名前（使い方の表示に使う）echo "使い方: $0 ..."
    $1 $2 …1番目、2番目の引数KEEP="$1"
    $#引数の個数[ "$#" -ge 1 ] || usage
    "$@"全引数を個々の値のまま渡す（通常はこちら）tar czf a.tgz -- "$@"
    shift引数を1つずつ前にずらす（順に処理するとき）while [ "$#" -gt 0 ]; do … shift; done
    return ／ exit関数から戻る ／ スクリプト全体を終了するreturn 1

    安全装置：set -euo pipefail と trap

    9.4節で set -eu を紹介した。運用スクリプトではこれに -o pipefail を足すことが多い。-e は失敗したら止める、-u は未定義変数をエラーにする、-o pipefail はパイプの途中が失敗したらパイプ全体を失敗扱いにする、である。3つ目がないと、ls ... | tail | xargs rm のような行で最初のコマンドが失敗しても素通りしてしまう。

    途中で終了したときの後始末には trap を使う。trap '処理' EXIT と書くと、正常終了でも異常終了でも、スクリプトを抜けるときに必ずその処理が走る。一時ファイルの削除やロックの解放はここに書く。

    冒頭に置く定型
    #!/bin/bash
set -euo pipefail
IFS=$'\n\t'                      # 単語の区切りを空白から改行とタブだけに絞る

TMP="$(mktemp -d)"               # 一時ディレクトリを安全に作る
cleanup() { rm -rf -- "$TMP"; }  # 後始末
trap cleanup EXIT                # どんな終わり方でも cleanup を実行する

echo "作業用: $TMP"
    traptrap 処理 EXIT
    スクリプトが終了するときや、中断（Ctrl+C）を受け取ったときに実行する後始末を登録する組み込みコマンド。一時ファイルの削除を書いておけば、途中で失敗してもゴミが残らない。
    よくある誤解・トラブル set -u を付けたら "$1" の参照でスクリプトが止まった

    引数が渡されていないと $1 は未定義であり、-u はそれをエラーにする。"${1:-}" と既定値を書くか、[ "$#" -ge 1 ] || usage で先に個数を検査する。

    ヒアドキュメントとログ関数

    複数行のテキストをそのままコマンドに渡したり、ファイルに書き出したりするにはヒアドキュメントを使う。区切り語を引用符で囲む（<<'EOF'）と中身は展開されず、囲まなければ変数が展開される。設定ファイルの雛形を書き出すときに便利である。

    あわせて、運用スクリプトには必ずログ関数を用意する。「いつ、何をして、成功したか失敗したか」が残っていないスクリプトは、自動実行した瞬間にブラックボックスになる。第4回 4-2のbackup.shが backup.log に1行ずつ記録しているのは、この考え方の最小形である。

    ヒアドキュメントとログ関数
    #!/bin/bash
set -euo pipefail
LOG="$HOME/work.log"

log() { echo "$(date '+%F %T') $*" >> "$LOG"; }   # 時刻付きで1行追記
die() { log "ERROR $*"; echo "$*" >&2; exit 1; }  # 記録してから異常終了

log "処理を開始した"
[ -d "$HOME/server" ] || die "server ディレクトリがない"

# 変数を展開してファイルへ書き出す
cat > "$HOME/report.txt" <<EOF
ホスト名: $(hostname)
日時: $(date '+%F %T')
EOF

# 展開させたくないときは区切り語を '' で囲む
cat > "$HOME/note.txt" <<'EOF'
$HOME はそのままの文字として書き出される
EOF

log "処理を終了した"
    ヒアドキュメントhere document / <<EOF
    複数行のテキストをその場でコマンドの入力やファイルの中身として与える書き方。区切り語を <<'EOF' のように引用符で囲むと、中の $ が展開されない。
    実習ではここで使う

    ※ 日付入りのファイル名とログ追記は第4回 4-2 シェルスクリプト（backup.sh）で、case による振り分けと引数の受け取りは第6回 6-1の自動化テーマで、そのまま使える形である。

    9.6安全なスクリプトの作法

    スクリプトは人が見ていない時間に動く。だからこそ、手で打つときには気にしなくてよかったことが問題になる。ここでは、事故を起こしたスクリプトに共通する原因と、その潰し方をまとめる。

    パスは絶対で書き、一時ファイルは mktemp で作る

    スクリプトは実行時のカレントディレクトリが分からない。相対パスで書くと、手で動かしたときだけ成功し、cronから動かすと別の場所を触る。$HOME か絶対パスで書き、どうしても移動が必要なら cd "$DIR" || exit 1 と失敗を捕まえる。

    一時ファイルを /tmp/work.txt のような固定名で作るのも危険である。他人（や自分の二重起動）と衝突するうえ、共有ディレクトリでは先回りして作られたファイルを掴まされる恐れがある。mktemp は衝突しない名前で、所有者だけが読み書きできる権限のファイルを作ってくれる。

    mktemp の使い方
    mktemp # 一時ファイルを作り、そのパスを表示する
/tmp/tmp.9kQ2fVb1Ac
mktemp -d # 一時ディレクトリを作る
/tmp/tmp.Hs7mWq0Tzr
ls -ld /tmp/tmp.Hs7mWq0Tzr
drwx------ 2 taro taro 4096 Sep 19 14:20 /tmp/tmp.Hs7mWq0Tzr

    出力の drwx------ に注目してほしい。所有者以外は読むことも入ることもできない。これが固定名の一時ファイルとの決定的な違いである（パーミッションの読み方は第5章）。

    破壊的な操作の前に確認を入れる

    削除や上書きを含む行は、書いた直後に必ず「空だったらどうなるか」を考える。実際に消す前に、対象の一覧を表示して目で確かめる手順を挟むのが確実である。

    削除の前に一覧を出す
    #!/bin/bash
set -euo pipefail
DEST="${DEST:?保存先が未設定}"   # 空なら即座に停止する
KEEP=7
cd "$DEST" || exit 1

# まず対象を数え、表示する（DRYRUN=1 で実行すると消さずに確認だけ）
TARGETS="$(ls -1t world_*.tar.gz 2>/dev/null | tail -n +$((KEEP+1)) || true)"
[ -n "$TARGETS" ] || { echo "削除対象なし"; exit 0; }
echo "$TARGETS"
[ "${DRYRUN:-0}" = "1" ] && exit 0
echo "$TARGETS" | xargs -r rm --
    注意

    ※ rm -rf "$DIR"/ のように末尾へスラッシュを足したり、変数が空になったりすると、削除範囲が意図せず広がる。書いたら必ず DRYRUN=1 のような確認経路で一度動かし、表示された一覧が想定どおりであることを目で確認してから本番で動かすこと。chmod -R 777 で権限の問題を「解決」するのも同類の事故であり、直すべきは所有者である（第5章）。

    shellcheck で静的に検査する

    shellcheckは、スクリプトを実行せずに読んで、引用符の付け忘れや使われていない変数、移植性の問題を指摘してくれる静的検査ツールである。人が見落とす定番のミスをほぼ機械的に拾ってくれるので、書き終えたら必ず一度は通す習慣を付けたい。Debian系では apt で入る。

    shellcheck の導入と実行
    sudo apt update
sudo apt install -y shellcheck
shellcheck ~/backup.sh # 指摘の一覧を表示
shellcheck -S warning ~/backup.sh # warning 以上だけに絞る
shellcheck -f gcc ~/backup.sh # 1行1件の簡潔な形式で出す
    オプション意味例
    -S 重大度表示する重大度の下限（style / info / warning / error）shellcheck -S warning a.sh
    -f 形式出力形式。gcc は1行1件で読みやすいshellcheck -f gcc a.sh
    -e 番号指定した指摘番号を除外する（理由が説明できるときだけ）shellcheck -e SC2086 a.sh
    -xsource で読み込む別ファイルも追跡するshellcheck -x a.sh

    出力の読み方

    shellcheck の出力
    shellcheck ~/backup.sh
In /home/luanti/backup.sh line 12:
tar czf $DEST/world_$DATE.tar.gz -C $HOME/server world
        ^-- SC2086: Double quote to prevent globbing and word splitting.

For more information:
  https://www.shellcheck.net/wiki/SC2086 -- Double quote to prevent globbing...

    見るのは3点である。まず行番号（line 12）で場所を特定し、次に ^-- が指している列で「どの語」が問題かを知り、最後に SC で始まる番号を控える。番号はそのまま検索語になり、shellcheck.net のwikiに理由と直し方が載っている。SC2086（引用符の付け忘れ）と SC2164（cd の失敗を無視している）は、運用スクリプトで最も頻出する2つである。

    shellcheck静的検査
    シェルスクリプトを実行せずに読んで、引用符の付け忘れなど定番のミスを指摘するツール。sudo apt install -y shellcheck で導入でき、指摘には SC2086 のような番号が付く。

    cron から動かすときの注意

    cronの実行環境は、SSHでログインした対話シェルとは別物である。~/.bashrc は読まれず、PATHは短く、ホームディレクトリの前提も違う。「手では動くのにcronだと動かない」の原因はほぼここに集約される。

    • コマンドもファイルも絶対パスで書く（/usr/bin/docker、/home/luanti/backup.sh）。またはスクリプトの冒頭で PATH=/usr/local/bin:/usr/bin:/bin を明示する。
    • 標準出力と標準エラーをログに落とす（>> /home/luanti/backup.log 2>&1）。落とさないと、出力はメールに回されて事実上消える。
    • 実行ユーザを意識する。crontab -e はそのユーザのcronであり、$HOME もそのユーザのものになる。
    • まず env -i /bin/bash --noprofile --norc /home/luanti/backup.sh のように環境変数をほぼ空にして手元で試すと、cron相当の条件を再現できる。

    9.7実用例2本

    ここまでの文法と作法を使った、そのまま動く例を2つ示す。どちらも第6回 6-1の自動化テーマの出発点にできる。写して動かし、自分のサーバに合わせて数値やパスを変えてみてほしい。

    例1：サービスの死活確認と自動再起動

    サービスが落ちていたら再起動し、その事実をログに残すスクリプトである。systemdの Restart=on-failure があっても、起動直後に落ち続ける場合や、プロセスは生きているのに応答しない場合には、こうした外側からの監視が効く。systemctl is-active は稼働中なら終了コード0を返すので、if でそのまま判定できる。

    ~/watch-luanti.sh
    #!/bin/bash
# Luantiサービスの死活確認と自動再起動
set -uo pipefail
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
UNIT="luanti"
LOG="/home/luanti/watch.log"

log() { echo "$(date '+%F %T') $*" >> "$LOG"; }

if systemctl is-active --quiet "$UNIT"; then
  exit 0                                  # 正常。何も記録しない
fi

log "WARN $UNIT is not active. restarting"
systemctl restart "$UNIT"
sleep 5                                   # 起動を待つ

if systemctl is-active --quiet "$UNIT"; then
  log "INFO $UNIT restarted"
else
  log "ERROR $UNIT failed to restart"
  journalctl -u "$UNIT" -n 20 --no-pager >> "$LOG"   # 直近のログを証拠として残す
  exit 1
fi

    このスクリプトは systemctl restart を実行するため、root権限が要る。rootのcron（sudo crontab -e）に登録するのが素直である。set -e をあえて外しているのは、systemctl restart が失敗した場合でも止まらずに、後段で失敗を記録し直近のログを残すためである（if の条件に書いたコマンドの失敗では、set -e はもともと発動しない）。

    rootのcronに5分ごとで登録する
    sudo chmod +x /home/luanti/watch-luanti.sh
sudo crontab -e
（エディタが開いたら次の1行を追記して保存する）
*/5 * * * * /home/luanti/watch-luanti.sh >> /home/luanti/watch.log 2>&1
sudo crontab -l # 登録内容の確認
    注意

    ※ 自動再起動は「落ちた事実」を隠してしまう仕掛けでもある。再起動した回数がログに増え続けているのに気付かなければ、根本原因は放置されたままになる。watch.log を定期的に見ること、そして落ちた原因（journalctl -u luanti -p err）を必ず1度は読むことをセットにする。

    例2：ディスク使用率の警告

    ディスクが満杯になると、ログもバックアップも書けなくなり、サービスが不可解な壊れ方をする。使用率がしきい値を超えたら記録して知らせるスクリプトを用意しておくと、満杯になる前に手を打てる。df の出力から使用率だけを取り出し、% を外して数値として比較するのが要点である。

    ~/disk-check.sh
    #!/bin/bash
# ルートパーティションの使用率がしきい値を超えたら警告する
set -euo pipefail
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
THRESHOLD="${1:-80}"                 # 引数で変えられる。既定は80パーセント
TARGET="/"
LOG="$HOME/disk.log"

USED="$(df --output=pcent "$TARGET" | tail -n 1 | tr -dc '0-9')"
[ -n "$USED" ] || { echo "使用率を取得できない" >&2; exit 1; }

if [ "$USED" -ge "$THRESHOLD" ]; then
  echo "$(date '+%F %T') WARN $TARGET is ${USED}% (threshold ${THRESHOLD}%)" >> "$LOG"
  du -xh --max-depth=1 "$HOME" 2>/dev/null | sort -h | tail -n 5 >> "$LOG"
  exit 1                             # 異常を終了コードでも伝える
fi

echo "$(date '+%F %T') INFO $TARGET is ${USED}%" >> "$LOG"

    出力の読み方

    動作の確認
    chmod +x ~/disk-check.sh
~/disk-check.sh 10 # しきい値を10にして、わざと警告させる
echo "終了コード: $?"
終了コード: 1
tail -n 3 ~/disk.log
2026-09-19 14:32:05 WARN / is 27% (threshold 10%)
180M	/home/taro/backup
1.2G	/home/taro

    1行目が判定の結果で、使用率としきい値が両方記録されている点が重要である。あとから見たときに「何パーセントで鳴ったのか」が分かるからである。続く行は容量を食っている上位のディレクトリで、警告が出たらまずここを見る。終了コードを1にしてあるので、cronから呼ぶ側でも失敗として扱える。
